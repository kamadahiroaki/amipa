# アトラスの中身

アトラス = 1 つのディレクトリ。丸ごとコピーすれば別のマシンでそのまま開ける。

```
graph.amipa/
  manifest.json              版・能力・sha256（何が入っているかの目録）
  graph.db           本体（多層 SQLite）
  graph.db.distill/  任意: 塩基レベルの整列表示に使う中間データ（シンボリックリンクではなく実体）
  graph.db.annot     任意: アノテーション（バンド・遺伝子・領域）
  graph.db.reads     任意: リード整列の索引（チャンク追記型: サンプルを後から足せる）
  graph.db.tiled     任意: 描画用のタイル索引。ノードとエッジをタイル順に並べ直したもので、
                     あると表示範囲の取得が速くなる（無ければ本体の空間索引で動く）。
                     エッジの行にはハプロタイプ幅とリード支持も写してあり、線の太さの表示で
                     本体や graph.db.reads を辺ごとに引かずに済む
  graph.db.synteny   任意: 共線ブロック（木）の索引。Blocks パネルの階層・アレル行列・接合はこれを引く
  graph.db.genes     任意: 遺伝子サイドカー。株ごとの GFF を欠けなく持つ（下記）
  reads/                     任意: リードの実体（seekable zstd の GAF）
  work/                      中間生成物とログ（部分的なやり直しに使う。配布時は削ってよい）
  state.json                 どの段まで終わったかの記録
```

## 決まりごと

- サイドカーは本体と 1 対 1。ファイル名は `<本体のファイル名>.<種類>` で対応づける。
  別のビルドのものを混ぜると、索引が別の場所を指して黙って壊れる。
  移動するときはアトラス単位で丸ごと。
- `manifest.json` に各ファイルの sha256 を記録してあるので、取り違えは検出できる。
- `.distill` はシンボリックリンクではなくディレクトリの実体として置く。
  リンクだと別マシンへ移した時点で切れる。
- リードの実体（`reads/`）は索引から相対的に探すので、アトラスごと移動しても追随する。
- リードの実体は入力 GAF そのままではない。行単位で取り出せるように zstd の独立フレームへ
  詰め直し、表示に使わないタグ（既定で塩基クオリティ `bq:Z`）を落としてある。
  何を落としたかは索引の `read_meta.dropped_tags` に記録される。
  `zstd -d` でそのまま伸長できる（末尾のシークテーブルは読み飛ばされる）。

## 遺伝子サイドカー（graph.db.genes）

株ごとの GFF3 をそのまま持ち、閲覧器が行ごとに遺伝子・CDS・エキソンを置くための表。
入力の GFF は 1 行も落とさず、`GET /api/blocks/gff?db=&acc=` で入力どおりに書き出せる。

| 表 | 内容 |
|---|---|
| `feature` | GFF の全データ行。9 列をそのまま（`attrs` は第 9 列の原文）、`id`・`parent`（最初の Parent の行）・`gid`（属する遺伝子）・`lineno` |
| `feature_tok` | 各行のトークン範囲（グラフのパスにある seqid の行だけ） |
| `gff_header` | `#` で始まる行（`##gff-version`、`##sequence-region` など） |
| `gene` / `gene_tok` / `gene_atom` | 閲覧器が描く単位（gene・pseudogene・RNA など。CDS は gene に併合）とトークン範囲・原子 |
| `junc_gene` | 再編成の接合と遺伝子の関係 |
| `orthogroup` / `gene_orth` | ノード共有で束ねた遺伝子群と各遺伝子の所属 |

`meta.format` が 2 以上なら `feature` 以下がある。1 のサイドカーでも遺伝子単位の表示は動く。

## 本体（多層 SQLite）に入っているもの

| テーブル | 内容 |
|---|---|
| `nodes` / `edges` | 各解像度層のノードとエッジ（座標・半径・向き・サイズ・被覆） |
| （`nodes_rtree`） | 旧形式の空間索引。現在は本体に持たず、`graph.db.tiled` が空間索引を担う（旧アトラスにあれば `.tiled` が無いときだけ使われる） |
| `stats` | 層ごとのノード数と、どのズームでどの層を出すかの較正値 |
| `node_contig_cov` ほか | どのハプロタイプがどのノードを通るか（リボン表示・絞り込み） |
| `ref_contigs` / `nodes.ref_bp` | 参照座標（座標での検索・座標軸表示） |
| `leaf_seq` | 葉ノードの塩基配列 |
| `db_meta` | 版・作成日時・入っている機能の一覧（`features`） |

閲覧側は `features` と実ファイルの有無を見て、使える機能だけを出す。
足りないものがあっても壊れずに、その機能だけ無効になる。

## 点検

```bash
amipa check                 # DB_DIR の全アトラス
amipa check graph.db
```

必須テーブル・空間索引・サイドカーの有無・Python 依存までを、全走査せずに確認する
（巨大なアトラスでも数秒）。
