# アトラスの中身

アトラス = **1 つのディレクトリ**。丸ごとコピーすれば別のマシンでそのまま開ける。

```
graph.amipa/
  manifest.json              版・能力・sha256（何が入っているかの目録）
  graph.db           本体（多層 SQLite）
  graph.db.distill/  任意: 塩基レベルの整列表示に使う中間データ（★実体ディレクトリ）
  graph.db.annot     任意: アノテーション（バンド・遺伝子・領域）
  graph.db.reads     任意: リード整列の索引
  reads/                     任意: リードの実体（seekable zstd の GAF）
  work/                      中間生成物とログ（部分的なやり直しに使う。配布時は削ってよい）
  state.json                 どの段まで終わったかの記録
```

## 決まりごと

- **サイドカーは本体と 1 対 1**。ファイル名は `<本体のファイル名>.<種類>` で対応づける。
  別のビルドのものを混ぜると、索引が別の場所を指して**黙って壊れる**。
  移動するときは**アトラス単位で丸ごと**。
- `manifest.json` に各ファイルの sha256 を記録してあるので、取り違えは検出できる。
- `.distill` は**シンボリックリンクではなくディレクトリの実体**として置く。
  リンクだと別マシンへ移した時点で切れる。
- リードの実体（`reads/`）は索引から**相対的に**探すので、アトラスごと移動しても追随する。
- リードの実体は**入力 GAF そのままではない**。行単位で取り出せるように zstd の独立フレームへ
  詰め直し、表示に使わないタグ（既定で塩基クオリティ `bq:Z`）を落としてある。
  何を落としたかは索引の `read_meta.dropped_tags` に記録される。
  `zstd -d` でそのまま伸長できる（末尾のシークテーブルは読み飛ばされる）。

## 本体（多層 SQLite）に入っているもの

| テーブル | 内容 |
|---|---|
| `nodes` / `edges` | 各解像度層のノードとエッジ（座標・半径・向き・サイズ・被覆） |
| `nodes_rtree` | 空間索引。表示範囲の取得はここから始まる |
| `stats` | 層ごとのノード数と、どのズームでどの層を出すかの較正値 |
| `node_contig_cov` ほか | どのハプロタイプがどのノードを通るか（リボン表示・絞り込み） |
| `ref_contigs` / `nodes.ref_bp` | 参照座標（座標での検索・座標軸表示） |
| `leaf_seq` | 葉ノードの塩基配列 |
| `db_meta` | 版・作成日時・**入っている機能の一覧**（`features`） |

閲覧側は `features` と実ファイルの有無を見て、使える機能だけを出す。
足りないものがあっても**壊れずに、その機能だけ無効**になる。

## 点検

```bash
amipa check                 # DB_DIR の全アトラス
amipa check graph.db
```

必須テーブル・空間索引・サイドカーの有無・Python 依存までを、**全走査せずに**確認する
（巨大なアトラスでも数秒）。
