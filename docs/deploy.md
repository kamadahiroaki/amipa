# クラウドで公開する

単一の VM で足りる。アトラスは SQLite なので**データベースサーバは要らない**。

```
[ブラウザ] ──HTTPS──▶ [リバースプロキシ(TLS)] ──▶ [amipa-viewer コンテナ]
                                                   └─ アトラス（ローカルディスク, 読み取り専用）
```

手順の一式（VM 作成 → 転送 → 起動 → 更新 → 監視 → 公開前チェック）は
[`../deploy/azure/README.md`](../deploy/azure/README.md) にある（Azure の例。他のクラウドでも考え方は同じ）。

## 押さえるべき点

1. **アトラスはブロックストレージ（ローカルディスク）に置く。**
   オブジェクトストレージやネットワークファイルシステムに置くと、細かいランダム読みが支配的な
   このアクセスパターンでは実用にならない。
2. **公開時は `AMIPA_READONLY=1`。** 編集の保存経路を塞ぐ。アトラス自体も読み取り専用でマウントする。
3. **同時アクセスの上限を決める。** 重い表示要求が 1 本入ると他の応答が待たされる構造なので、
   `AMIPA_MAX_ROWS` / `AMIPA_FETCH_MS` と前段のレート制限で守る。
4. **メモリはページキャッシュとして効く。** アトラス全体が載らなくても、よく見られる範囲が残る。
5. **費用の見張りを先に設定する。** 大きなアトラスを常時公開するとストレージ費用が効いてくる。

## 更新

イメージのタグを上げるだけ。**アトラスは触らない**。

```bash
docker compose pull && docker compose up -d
curl -s https://<host>/api/version
```
