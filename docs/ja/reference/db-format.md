# DB の形式

[English](../../en/reference/db-format.md)

AMIPA の DB は 1 つのディレクトリで、本体（多層の SQLite）と、その横に置く付属ファイル（サイドカー）からなる。丸ごとコピーすれば、別のマシンでそのまま開ける。各ファイルを作る段は [前処理の各段](pipeline.md) にある。

## ディレクトリの中身

```
graph.amipa/
  manifest.json        目録（版・入っているもの・各ファイルの大きさと sha256）
  graph.db             本体（多層 SQLite）
  graph.db.tiled       必須: 描画用のタイル索引（閲覧側の唯一の空間の索引）
  graph.db.distill/    任意: パスの通り道と塩基配列の中間データ（Linear の塩基の段の材料）
  graph.db.annot       任意: 参照の注釈をノードに写したもの（染色体バンド・遺伝子・領域）
  graph.db.reads       任意: リードの整列の索引（チャンク追記型。サンプルを後から足せる）
  graph.db.trav        任意: Linear の索引（錨・合意座標・通過・境界）。パスがあれば既定で作る
  graph.db.travx       任意: .trav と一緒に作る。合意座標の範囲の索引（と配列のファイル .travx.arr）
  graph.db.xtiles      任意: .trav と一緒に作る。通過を合意座標の区画ごとにまとめたもの
  graph.db.anc         任意: .trav と一緒に作る。元のノードから各層の祖先への対応
  graph.db.refx        任意: .trav と一緒に作る。パスの座標と合意座標の対応点（座標での移動・BED の書き出し）
  graph.db.tiledx      任意: .tiled と同じ並びでノードの合意座標を持つ（Linear があるとき）
  graph.db.xdepth      任意: 合意座標ごとのリードの深さ（リードと .trav があるとき）
  graph.db.genes       任意: 株ごとの遺伝子。入力の GFF を欠けなく持つ（下記）
  graph.db.genex       任意: .genes と一緒に作る。遺伝子の帯の索引と機能喪失の目安
  graph.db.gsearch     任意: .genes と一緒に作る。遺伝子の検索の索引
  graph.db.ann         任意: 参照の座標の注釈（RepeatMasker の反復、サンプルの変異とベンチマーク領域）
  graph.db.segnames    任意: 内部のノード名と元のセグメント名の対応（整数でない id のグラフだけ）
  graph.db.rlabel      任意: リードのラベル（例: 父由来・母由来）
  graph.db.collapse    任意: 畳んだバブルの差分と元のノードとの対応（--collapse のとき）
  reads/               任意: リードの実体（seekable zstd の GAF）
  work/                中間物とログ（再開に使う。配布するときは削ってよい）
  state.json           どの段まで終わったかの記録
```

用語:

- 層: 解像度の段階。粗い層ほど、1 つのノードが多くの元のノードを代表する。最も細かい層のノード（葉）が元のグラフのセグメントにあたる。
- 錨・合意座標・通過: Linear の横軸を作るための概念（[前処理の各段](pipeline.md#linear-の索引を作る)）。

## 決まりごと

- サイドカーは本体と 1 対 1 で、ファイル名 `<本体のファイル名>.<種類>` で対応づける。別のビルドのものを混ぜると、索引が別の場所を指して黙って壊れる。移すときは DB のディレクトリ単位で丸ごと移す。名前を変えるときはサイドカーも同じ名前に揃える。
- `manifest.json` に各ファイルの sha256 を記録してあるので、取り違えは検出できる（`--hash-limit-gb` を超えるファイルは省く）。
- `.distill` はシンボリックリンクではなく、ディレクトリの実体として置く。リンクだと別のマシンへ移した時点で切れる。
- リードの実体（`reads/`）は索引から相対的に探すので、DB ごと移しても追随する。
- リードの実体は入力の GAF そのままではない。行単位で取り出せるように zstd の独立した塊へ詰め直し、表示に使わないタグ（既定で塩基クオリティ `bq:Z`）を落としてある。何を落としたかは索引の `read_meta.dropped_tags` に記録される。`zstd -d` でそのまま伸長できる（末尾の位置の表は読み飛ばされる）。
- `.tiled` は必須。無い・古い形式（v4 より前）・空のときは閲覧できない（`amipa prep add-tiled` で作り直す）。
- 本体の名前は `<name>.db`。古い DB の `<name>.layered.db` もそのまま読める。

## 本体

多層の SQLite。

| 表 | 内容 |
|---|---|
| `nodes` / `edges` | 各層のノードと辺（座標・半径・向き・大きさ・被覆） |
| `stats` | 層ごとのノード数と、どの拡大率でどの層を出すかの較正値 |
| `node_contig_cov` ほか | どのハプロタイプがどのノードを通るか（帯の表示・絞り込み） |
| `ref_contigs` / `nodes.ref_bp` | 参照座標（座標での検索・座標の表示） |
| `leaf_seq` | 葉ノードの塩基配列 |
| `db_meta` | 版・作成日時・入っている機能の一覧（`features`） |

閲覧側は `features` と実際のファイルの有無を見て、使える機能だけを出す。足りないものがあっても全体は壊れず、その機能だけが無効になる。

古い形式の空間の索引（`nodes_rtree`）と、ハプロタイプの絞り込みの索引（`.hapidx`）は今は使わない。古い DB に残っていても閲覧側は読まない。空間の索引は `.tiled` が持つ。

## タイル索引

`graph.db.tiled`。ノードと辺を層ごとにタイル順（Z-order）に並べ直したもの。ハプロタイプの絞り込み用のマスクも持つ。辺の行にはハプロタイプの数とリードの支持も写してあり、線の太さの表示で本体や `.reads` を辺ごとに引かずに済む。`meta` の `schema` が形式の版。

## 遺伝子

`graph.db.genes`。株ごとの GFF3 をそのまま持ち、閲覧側が行ごとに遺伝子・CDS・エキソンを置くための表。入力の GFF のうち、グラフのパスにある seqid の行と `#` の行は 1 行も落とさず、`GET /api/trav/gff?db=&acc=` で入力どおりに書き出せる（`acc` は GFF のファイル名＝パス名のサンプル）。グラフに無い seqid の行は読まない。

| 表 | 内容 |
|---|---|
| `feature` | GFF の全データ行。9 列をそのまま（`attrs` は第 9 列の原文）、`id`・`parent`（最初の Parent の行）・`gid`（属する遺伝子）・`lineno` |
| `feature_tok` | 各行のパス上の範囲（グラフのパスにある seqid の行だけ） |
| `gff_header` | `#` で始まる行（`##gff-version`、`##sequence-region` など） |
| `gene` / `gene_tok` | 閲覧側が描く単位（gene・pseudogene・RNA など。CDS は gene に併合）と、そのパス上の範囲。注釈の無いパスへノードの共有で写した遺伝子は `proj`（写した元）と `frac`（一致率）を持つ |

`meta.format` が 2 以上なら `feature` 以下がある。1 のサイドカーでも遺伝子単位の表示は動く。

写しには `gene_qc(gid, unanch)` が付く（CDS の端を元に揃えられなかった数。1 以上なら機能喪失の目安は判定しない）。

### 遺伝子の帯の索引と機能喪失の目安

`graph.db.genex`。`g_b` の 1 行が遺伝子（写しを含む）1 つ。`lof_st` は機能喪失の目安で、値は `meta.lof_states` の並び（`ok,fs,trunc,nostart,nocds,partial,refdiff`。後ろの 2 つは後から足したので、古い索引には 0〜4 しか無い）。

| 値 | 名前 | 意味 |
|---|---|---|
| 0 | `ok` | 変わらない |
| 1 | `fs` | CDS の長さの差が 3 の倍数でない（フレームシフト） |
| 2 | `trunc` | 最初の終止コドンまでが元の 9 割未満 |
| 3 | `nostart` | 元にある開始コドンが無い |
| 4 | `nocds` | CDS が無い、または組み立てられない |
| 5 | `partial` | 判定しない。写しが部分的（CDS の片が元より少ない）、CDS の端を元に揃えられない、元の注釈が擬似遺伝子・部分的な遺伝子（`partial=true`、`cds_start_NF` など） |
| 6 | `refdiff` | 元と違う（1〜3 のどれか）が、判定できる写しの 9 割以上（5 本以上）が同じ違いを持つ。元（参照）の側が外れ値と見込まれる |

写しは、写した元の遺伝子の同じ転写産物と比べる。転写産物は `MANE_Select`、`Ensembl_canonical`、CDS の長さの順で選び、`protein_coding_LoF`・`nonsense_mediated_decay`・`cds_start_NF`／`cds_end_NF` の転写産物は（他にあれば）使わない。`transl_except` に Sec があるか `stop_codon_redefined_as_selenocysteine` の行がある転写産物は、TGA を終止としない。`transl_table=11` の遺伝子は CTG・ATT・ATC・ATA も開始コドンとみなす。

## Linear の索引

`graph.db.trav`。Linear パネル（ブロック・錨の列・ノード・塩基の段）の材料。`.distill`（パスの通り道）から作る。

- 錨: ハプロタイプの中で 1 回だけ通り、多くのハプロタイプが同じ順で通るノード。錨の並びが合意座標（横軸）になる。
- 通過: 1 本のコンティグが合意座標の単調な区間を通ること。同じ区間を 2 回通れば通過も 2 つ（重複）。
- 境界: 通過の端と、通過するハプロタイプの数が変わる所。境界で切った最小の区間を原子と呼ぶ。

| 表 | 内容 |
|---|---|
| `haps` / `paths` | ハプロタイプとパス（コンティグ）。同じ株の他のコンティグに丸ごと含まれるコンティグは `excluded` |
| `trav` | 通過: パス・パス上の範囲（`i0`〜`i1`）・合意座標の範囲（`x0`〜`x1`）・向き・コピー番号・錨の数・bp |
| `copies` / `reps` | 同じコンティグの通過どうしの重なり（重複）と、ハプロタイプの中で 2 回以上出るノードの連なり（反復） |
| `bounds` / `atoms` | 境界（支持するハプロタイプの数・持続度）と原子 |
| `super` | 上の層のノードの合意座標（子孫の葉の多数派） |
| `arrays` | ノード → 合意座標（`x_of_dense`、錨でないノードは `x_fill`）、合意座標 → ノード（`dense_of_x`）、合意座標ごとの累積 bp（`xbp`）など |

合意座標の向きと順は参照のパス（[参照の決まり方](../setup/03-your-data.md#参照の決まり方)）を手掛かりに決め、複数の染色体は参照の順に並べる。

## セグメント名

`graph.db.segnames`。SQLite。`segs(id, name)` が内部の番号（葉の名前 `n<id>` の数字）と元のグラフのセグメント名の対応で、`name` に索引がある。セグメント id がすべて整数のグラフでは作らない（内部の名前 `n<id>` の `n` を外したものが元の id）。閲覧側は表示・検索・書き出しのときだけ引く。

## リードのラベル

`graph.db.rlabel`。SQLite。`label(lid, sample_no, label)` がサンプルごとのラベルの辞書、`aln_label(aln_id, lid)` が整列 → ラベル。`meta` の `reads_size` は作ったときの `graph.db.reads` の大きさで、閲覧側は合わなければ（リードの索引を作り直した後）このファイルを使わない。表に無い整列はラベル無しで、ラベルを持つサンプルの中では「no label」として並ぶ。

## 点検

```bash
amipa check                 # DB_DIR の全 DB
amipa check graph.db
```

必須の表、層の数、タイル索引、注釈・リード・セグメント名のサイドカーの有無を、全体を読み通さずに確かめる（大きな DB でも数秒）。

DB の形式を変えたリリースでは、何が変わったかをこのページに書く。
