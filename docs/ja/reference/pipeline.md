# 前処理の各段

[English](../../en/reference/pipeline.md)

`amipa prep run` は GFA を、いくつかの段（工程）を順に通して多解像度の DB に変える。各段の出力は DB のディレクトリ（中間物は `work/`）に残るので、途中から再開できる（[途中から再開する](../setup/04-large-graphs.md#途中から再開する)）。段の名前は `--from`・`--only` に渡す名前（[コマンドと選択肢](cli.md#段の制御)）。

```
GFA ─ distill ─▶ 配列にした中間 ─ decompose ─▶ バブルの木
                     │                              │
                     └──────── lod ◀────────────────┘
                                │
                         解像度の階層 ─ layout ─▶ 座標 ─ emit ─▶ 多層 SQLite（本体）
                                                                    │
            trav（Linear）・genes・ann・annot・reads・rlabel・xdepth ◀─┤
                                                                    │
                                                     tiled（タイル索引）─ bundle（目録）
```

| 段 | 何をするか | 走る条件 |
|---|---|---|
| `distill` | GFA を読み込む | 常に |
| `collapse` | 自明なバブルを畳む | `--collapse` |
| `decompose` | バブルを見つける | 常に |
| `lod` | 解像度の階層を組む | 常に |
| `layout` | 2 次元に配置する | 常に |
| `emit` | 多層の DB を書く | 常に |
| `trav` | Linear の索引を作る | パスがあるとき（`--no-trav` で外す） |
| `genes` | 株ごとの遺伝子を写す | `--gff-dir` |
| `ann` | 参照の注釈を持つ | `--ann-rmsk`・`--ann-vcf`・`--ann-bed` |
| `annot` | 参照の注釈をノードに写す | `--band`・`--gene`・`--region`（パスがあるとき） |
| `reads` | リードを取り込む | `--reads` |
| `rlabel` | リードにラベルを付ける | `--read-labels` |
| `xdepth` | リードの深さを数える | リードと Linear の索引があるとき |
| `tiled` | 描画用のタイル索引を作る | 常に（`--no-tiled` で外すと閲覧できない） |
| `bundle` | 目録を作る | 常に（最後に必ず作り直す） |

## GFA を読み込む

段の名前: `distill`

GFA を 1 回だけ読み、ノード・辺・パス・塩基配列を、密な整数の番号で引ける配列に落とす。以降の段は GFA を読まない。全ゲノム規模ではここが唯一の全文の読み込みになる。

- 圧縮（`.gz`・`.zst`）のまま読む。
- 重なりのある L 行（CIGAR が `0M`・`*` でない）が 1 本でもあれば、例を示して止まる。
- GFA ヘッダの `RS:Z`（参照のサンプル）を記録し、参照の選び方に使う（[参照の決まり方](../setup/03-your-data.md#参照の決まり方)）。
- セグメント id に整数でないものがあれば、S 行の順に内部の番号を振り、元の名前を `<db>.segnames` に書く。

## 自明なバブルを畳む

段の名前: `collapse`（`--collapse` のときだけ）

SNP のような 1 塩基の分岐の連なり（自明なバブルの連鎖）を 1 ノードに畳んだ GFA を作り、それを読み込み直す。以降の段は畳んだグラフだけを見る。アレルの差分と元のノードとの対応は `<db>.collapse` に入る。

## バブルを見つける

段の名前: `decompose`

グラフの中の、入れ子になったバブル（分岐して再び合流する部分）を見つけ、木として書き出す。外部のツールを 1 つ選んで使う（`--decomposer`）。

| 分解器 | 特徴 |
|---|---|
| `bubblefinder`（既定） | [BubbleFinder](https://github.com/algbio/BubbleFinder) の ultrabubble。最も速く軽い（全ゲノム規模で数分・数十 GB）。ただし内部に閉路を含むバブル（縦列反復や環状ゲノムの一部）は定義上出さないので、その部分は次の段で細切れの階層になる |
| `billi` | [Billi](https://github.com/at-cg/billi) の panbubble。閉路を含むバブルも見つけ、入れ子の親子関係もより正しく出す。BubbleFinder より数倍遅く重い。1 スレッド |

どちらの分解器でも出力は同じ形式に揃え、次の段はそれだけを読む。分解の前に入力からパス（P・W 行）を除く。端の無い連結成分（純粋な環）があると分解器が止まるので、そのときだけ成分ごとに分岐の無い 1 点で環を開いてやり直し、結果を元のノードに戻す。

配布しているイメージには Billi が入っていない（Billi のリポジトリにはライセンスの表示が無く、再配布できないため）。Billi を使うときは自分で入手してビルドし、`--billi` で場所を渡す（環境変数 `AMIPA_BILLI` でもよい）。

分解器ごとにバブルの呼び名が違う（BubbleFinder は ultrabubble、Billi は panbubble）が、AMIPA では一貫して「バブル」と呼ぶ。

## 解像度の階層を組む

段の名前: `lod`

バブルの木とグラフのコミュニティ構造（Infomap）を 1 本の木にまとめ、どのノードをどの解像度で見せるかを決める。この木の深さごとの段階を層と呼ぶ。粗い層ほど、画面上の 1 つのノードが多くの元のノードを代表する。

各ノードは、それを内部に含む最も深いバブルに属させる（深いバブルから順に、入口から出口までの内部をたどって割り当てる。外側のバブルをたどるときは、内側のバブルに割り当て済みの部分も通り抜ける）。バブルの入れ子だけでは粒度が飛び飛びになり、コミュニティだけでは生物学的な構造と対応しないので、両方を合わせている。

この段は再現性のため 1 スレッドで固定している（並列にすると結果が変わる）。

## 2 次元に配置する

段の名前: `layout`

グラフのつながりだけから 2 次元の座標を決める（PivotMDS で初期化した確率的勾配降下）。ゲノムの 1 次元の並びに引きずられず、バブルの入れ子の構造が見える配置になる。多くのコアを使うのはこの段とバブル分解だけ。調整の選択肢は [レイアウトの調整](cli.md#レイアウトの調整)。

## 多層の DB を書く

段の名前: `emit`

層ごとにノードと辺を SQLite へ書き、検索の索引・参照座標・塩基配列・ハプロタイプの通過（どのハプロタイプがどのノードを通るか）を載せる。空間の索引は本体には持たず、後の `tiled` の段が別のファイルに作る。

この段はランダム書き込みが中心なので、`--tmp` にローカルの速いディスクを指定すると大幅に速くなる（共有ファイルシステム上で直接組むとネットワーク待ちになる）。

## Linear の索引を作る

段の名前: `trav`

画面下の Linear パネル（株ごとの行で、並び・向き・欠失・重複を比べる）の材料を作る。

- 錨（anchor）: 1 本のハプロタイプの中で 1 回だけ通り、多くのハプロタイプが同じ順で通るノード。株どうしの位置を合わせる目印になる。
- 合意座標（consensus coordinate）: 錨を多くのハプロタイプが通る順に並べた、全株に共通の横軸。Linear の横方向はこの座標。
- 通過: 1 本のコンティグが合意座標の上を単調に進む区間。同じ区間を 2 回通るコンティグは通過が 2 つになる（重複）。

参照のパスの並びを手掛かりに、合意座標の向きと染色体の順を決める。`<db>.trav` と一緒に、範囲を引くための索引（`.travx`・`.xtiles`・`.anc`・`.refx`）も作る（[DB の形式](db-format.md)）。

## 株ごとの遺伝子を写す

段の名前: `genes`

株ごとの GFF（GFF3・GTF）を流し読みし、グラフのパスにある seqid の行を、パスの上の範囲に写す（メモリは GFF の大きさではなく、グラフにある行の数で決まる）。注釈の無いパスへは、注釈のあるパスの遺伝子をノードの共有を手掛かりに写す。続けて、遺伝子の検索の索引と、写しごとの機能喪失の目安（CDS を組み立てて翻訳した結果）を前計算する（[DB の形式](db-format.md#遺伝子)）。

## 参照の注釈を持つ

段の名前: `ann`

RepeatMasker の表と、サンプルの VCF・BED を参照の座標のまま持つ（`<db>.ann`）。閲覧側が Linear の塩基の段で、列の参照の位置と突き合わせる。参照のパスに無いコンティグの行は読まない。

## 参照の注釈をノードに写す

段の名前: `annot`

染色体バンドの表・GTF/GFF3・BED を読み、参照のパスをたどって各ノードに写す（パスの無いグラフでは作らない）。外部ツールは使わない。本体は書き換えず、`<db>.annot` に書く。

## リードを取り込む

段の名前: `reads`

GAF を seekable zstd（256 KiB ごとの独立した圧縮の塊と、その位置の表）に詰め替え、索引だけを `<db>.reads` に置く。表示のときは該当する塊だけを伸長して 1 行を取り出す。表示に使わないタグ（既定 `bq:Z`）は保存しないので、同じ内容が BGZF の 1/8 に収まる。取り込みの前に、GAF のノード名と DB のノードの一致率を調べる。

## リードにラベルを付ける

段の名前: `rlabel`

「リード名<TAB>ラベル」の表を、リードの索引の整列の番号に写して `<db>.rlabel` に書く。整列とタイル索引は作り直さない。

## リードの深さを数える

段の名前: `xdepth`

合意座標ごとに、その座標をまたぐ整列の数をサンプルごとに数え、粗い段階（1・64・4,096 座標ごとの平均）で持つ。広い範囲のリードの厚みを、読み出すだけで描ける。

## 描画用のタイル索引を作る

段の名前: `tiled`

ノードと辺を層ごとにタイル順（Z-order）へ並べ直した別ファイル（`<db>.tiled`）を作る。表示範囲の取得、件数の見積もり、ハプロタイプの絞り込み、線の太さ（ハプロタイプの数・リードの本数）をすべてここから引く。画面の矩形の問い合わせがファイルの連続した範囲の読み出しになるので、ネットワークファイルシステム上の大きな DB でも表示範囲の取得が速い。閲覧側の唯一の空間の索引で、無いと DB を開けない。リードを足したときは作り直す。

## 目録を作る

段の名前: `bundle`

`manifest.json`（版・入っているもの・各ファイルの大きさと sha256）を作る。どの段を走らせても最後に作り直す。
