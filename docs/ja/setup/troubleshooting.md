# うまくいかないとき

[English](../../en/setup/troubleshooting.md)

症状から引く。まず閲覧イメージの `amipa check` を通すと、DB の側の問題かどうかが分かる（[最初の DB を作る](02-first-db.md#確かめる)）。

## 前処理

| 症状 | 原因と対処 |
|---|---|
| `Killed` で落ちる | メモリの上限。コンテナなら `--memory` を、ジョブならメモリの要求を増やす。段ごとの目安は `amipa prep plan`（[大きなグラフ](04-large-graphs.md#見積もるplan)） |
| 一時領域が足りない | `--tmp`（本体を組む場所）と `--spill`（途中の一時ファイル）を別々に指定する |
| 極端に遅い | `--tmp` が共有ファイルシステムを指している。起動時のログに、選ばれた場所とファイルシステムの種類が出る |
| 出力が root の所有になる | `docker run` に `-u "$(id -u):$(id -g)"` を付ける |
| 「重なりのある L 行が … 本ある」で止まる | 重なりのある（blunt でない）GFA。de Bruijn グラフ（Bifrost・Cuttlefish など）は、重なりを除いた GFA に変換してから渡す |
| 参照座標・座標での移動が画面に無い | 参照のパスが選べていない。ログの「参照: …（理由）」を見て、違えば `--ref-key` でサンプルを指定する（[参照の決まり方](03-your-data.md#参照の決まり方)） |
| 「--gff-dir … に、どのパスの GFF も無い」で止まる | ファイル名がパス名のサンプルと合っていない。表示された期待名（`<sample>.gff3.gz` など）に合わせる |
| 遺伝子が 0 件、または一部の株だけ遺伝子が無い | GFF の seqid（第 1 列）がパス名のコンティグと違う（例: GFF は `NC_001133.9`、パスは `S288C#0#chrI`）。遺伝子の段のログに「グラフの seqid の行が 1 行も無い」と出る |
| `--gene` で「seqid が一致する gene 行が無い」と止まる | seqid が参照のコンティグ名と違うか、gene 行の無い GTF（UCSC の `ncbiRefSeq.gtf` など）。後者は `--gff-dir` で渡す |
| `--band`・`--gene` を渡したのに注釈が付かない | パスの無いグラフ（rGFA・de Bruijn）では写せないので飛ばす（ログに出る）。パスのあるグラフなら、seqid と参照のコンティグ名の一致を確かめる |
| リードの取り込みが「GAF のノード名が DB の葉と一致しない」で止まる | 整列と DB のノード ID がずれている。`vg giraffe --named-coordinates` で整列したか、整列に使った GFA が DB の元と同じかを確かめる。承知の上で続けるなら `--reads-force-mismatch`。整数でない id のグラフでは、GAF も元の名前のまま渡す（[セグメント名](03-your-data.md#セグメント名)） |
| 何も変えていないのに段がやり直しになる | 入力ファイルの大きさか更新時刻が変わった（コピーし直した、など）。段の鍵は入力の署名を含む |

## 閲覧

| 症状 | 原因と対処 |
|---|---|
| DB が一覧に出ない | `DB_DIR`（コンテナでは `/data` へのマウント）の指定違い。`amipa check` で見えるか確かめる |
| 「空間索引（.tiled サイドカー）が無い」「形式が古い」で開けない | 描画用のタイル索引が無い・古い・空。`amipa prep add-tiled --out <DB のディレクトリ>` で作り直す（本体は作り直さない） |
| 画面とノード検索が `n123` のような内部名になる | 整数でない id のグラフで `<db>.segnames` が無い。`amipa prep run --out <DB のディレクトリ> --only distill` で作り直す |
| Linear の塩基の段だけ出ない | `<db>.distill` が無い、またはシンボリックリンクのまま別のマシンへ移した。`check` が警告する。ディレクトリの実体として置く |
| リードだけ出ない | `reads/` の実体が DB に入っていない。索引だけでは表示できない。`check` が指摘する |
| リードのラベルが付かない | リードを作り直した後でラベルを流し直していない。`amipa prep add-read-labels` をもう一度流す |
| ノード名の検索やサンプルの絞り込みが無い | その索引を作らずに DB を作っている。`check` が指摘する |
| 最初の操作が遅い | ディスクのランダム読み。DB をローカルディスクへ置く、メモリを増やす（[ディスクとメモリ](05-serve.md#ディスクとメモリ)） |
| 表示が一部欠ける | 重い要求が上限で打ち切られている。`AMIPA_MAX_ROWS`・`AMIPA_FETCH_MS` を緩める（[閲覧サーバの設定](../reference/viewer-config.md)） |
| Save を押せない | `AMIPA_READONLY=1` で起動している（公開インスタンスの正常な状態） |

## コンテナのビルド

| 症状 | 原因と対処 |
|---|---|
| 依存の取得で止まる | ビルドには外向きの通信が要る。プロキシの環境では設定を渡す |
| Apptainer の build がマウントで失敗する | サイトの設定の bind。`env -u APPTAINER_BINDPATH apptainer build ...` |
| 権限の拒否で起動できない | 元ファイルの権限がイメージに入り込んでいる。同梱の定義は対策済み |
| ライブラリが見つからない | 実行段のイメージに共有ライブラリが足りない。同梱の定義は焼くときに検査している |
| 思いがけない `import` のエラー | ホストの `~/.local` を拾っている。`--cleanenv` と `PYTHONNOUSERSITE=1`（同梱のイメージは設定済み） |
