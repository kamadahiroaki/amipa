# ライセンス

| 対象 | ライセンス | 理由 |
|---|---|---|
| `prep/`（前処理） | GPL-3.0-or-later | Infomap（GPL-3.0-or-later）を同一プロセスで読み込むため |
| `prep/amipa_prep/cs_ops.py` と `prep/amipa_prep/zstd_seek.py` | MIT | 閲覧側が同じ形式を読むために複製して使うファイルで、Infomap とは無関係なため（下記） |
| `viewer/`（閲覧） | MIT | コピーレフトの依存が無く、他のソフトに組み込みやすくするため |
| ドキュメント | CC BY 4.0 | |

リポジトリ直下の `LICENSE` は GPL-3.0（全体としての条件）、`viewer/LICENSE` が MIT です。
同梱物の一覧と入手元は [`../NOTICE`](../NOTICE) にあります。

## 前処理と閲覧で共有している 2 つのファイル

リード整列の容器（seekable zstd）と `cs:Z` の切り出しは、書く側（前処理）と読む側（閲覧）で
一致していなければならないので、実装を 1 か所に置いて共有しています。置き場は前処理側ですが、
閲覧イメージのビルド時に閲覧側へ複製されます。

この 2 つは Infomap を使わないので GPL にする理由がなく、MIT で提供します
（ファイル冒頭に `SPDX-License-Identifier: MIT` があります）。
これにより、配布する閲覧イメージに含まれる AMIPA のコードはすべて MIT になります。

## コンテナイメージを再配布するとき

イメージには AMIPA 以外のソフトウェアも入っています。

| イメージ | AMIPA のコード | 同梱している他のソフトウェア |
|---|---|---|
| `amipa-prep` | GPL-3.0-or-later | Infomap（GPL-3.0-or-later）、povu（MIT）、Python の各種、Debian のシステムパッケージ |
| `amipa-viewer` | MIT | Node.js、Debian のシステムパッケージ |

どちらのイメージも Debian をベースにしているため、GPL/LGPL のシステムパッケージを含みます。
そのまま再配布する分には、次の 2 つを満たせば足ります。

1. `NOTICE` を一緒に配る（イメージ内 `/opt/amipa/NOTICE` にも入っています。`amipa licenses` で表示できます）
2. GPL コンポーネントの対応するソースの入手方法を示す。同梱しているのは無改変の公開版なので、
   `NOTICE` に書いた入手元と版番号を示せば足ります

自分で改変した Infomap を含めて配布する場合は、その改変ソースの提供義務が生じます。

## AMIPA を組み込みたいとき

- 閲覧側だけを使う（アトラスを表示する機能を自分のソフトに組み込む）→ MIT なので自由。
  共有している 2 ファイルも MIT なので、閲覧側一式をそのまま取り込めます
- 前処理を含めて使う → GPL-3.0-or-later に従う（派生物も GPL で公開する）

前処理を permissive にしたい場合は、Infomap を別プロセスとして呼ぶ形に変えれば分離できます
（現在は Python API を同一プロセスで使用）。必要であれば issue で相談してください。
