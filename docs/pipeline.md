# 前処理は何をしているか

GFA を 5 段で多解像度アトラスに変える。各段の出力は `work/` に残るので、
途中からやり直せる。

```
GFA ─① 抽出 ─▶ 配列中間 ─② バブル分解 ─▶ バブル木
                    │
                    └─③ 統一 LOD 木 ─▶ 階層 ─④ レイアウト ─▶ 座標 ─⑤ アトラス化 ─▶ 多層 SQLite
```

### ① 抽出（distill）

GFA を **1 回だけ**走査し、ノード・エッジ・パス・塩基配列を密な整数 ID の配列に落とす。
以降の段は GFA を読まない。全ゲノム規模ではここが唯一の全文走査になる。

### ② バブル分解（decompose）

グラフの入れ子になった**バブル**（分岐して再合流する部分構造）を検出し、木として書き出す。
外部ツール [povu](https://github.com/pangenome/povu) を使う。

### ③ 統一 LOD 木

バブル木とグラフのコミュニティ構造（Infomap）を合わせ、**どのノードをどの解像度で見せるか**の
階層を作る。粗い層ほど 1 つのノードが多くの実ノードを代表する。
この段は**再現性のため 1 スレッド固定**（並列化すると結果が変わる）。

### ④ レイアウト

トポロジだけから 2 次元座標を決める（PivotMDS で初期化した確率的勾配降下）。
ゲノムの一次元性に引きずられず、バブルの入れ子構造が見える配置になる。

### ⑤ アトラス化（emit）

層ごとにノードとエッジを SQLite へ書き、空間索引・検索索引・ハプロタイプ索引・
参照座標・塩基配列を載せる。表示に必要なものはすべてこの段で作る。

**この段はランダム書き込みが支配的**なので、`--tmp` にローカルの速いディスクを指定すると
大幅に速くなる（共有ファイルシステム上で直接組むとネットワーク待ちになる）。

## 付随する段

| 段 | 何をするか |
|---|---|
| アノテーション | 参照座標やパスをたどって、バンド・遺伝子・領域を各ノードに射影する。**本体は書き換えず**サイドカーに書く |
| リード | GAF を BGZF 化して索引だけをサイドカーに置く。実体は必要な行だけ seek して読む |

どちらも**アトラスを作り直さずに後から足せる**。
