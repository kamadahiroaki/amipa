# うまくいかないとき

## 閲覧

| 症状 | 原因と対処 |
|---|---|
| DB が一覧に出ない | `DB_DIR` の指定間違い。`amipa check` で見えるか確認する |
| 整列パネルだけ出ない | `.distill` が無い、またはシンボリックリンクのまま移動した。`check` が警告する |
| リードだけ出ない | `reads/` の実体が DB に入っていない。索引だけでは表示できない |
| 検索やハプロタイプ絞り込みが無い | その索引を作らずに DB を構築している。`check` が指摘する |
| 最初の操作が遅い | ディスクのランダム読み。ローカルディスクへ置く／メモリを増やす |
| 表示が一部欠ける | 重い要求が上限で打ち切られている。`AMIPA_MAX_ROWS` / `AMIPA_FETCH_MS` を緩める |

## 前処理

| 症状 | 原因と対処 |
|---|---|
| `Killed` で落ちる | メモリ上限。コンテナなら `--memory` を増やす。段ごとの目安は [usage-prep.md](usage-prep.md) |
| 一時領域が足りない | `--tmp`（本体を組む場所）と `--spill`（一時ファイル）を別々に指定する |
| 極端に遅い | `--tmp` が共有ファイルシステムを指している。起動時のログに選ばれた場所と種別が出る |
| リード取り込みが「GAF のノード名が DB の葉と一致しない」と失敗する | 整列と DB の ID 空間がずれている。`--named-coordinates` で整列したか、整列に使った GFA が DB の元と同じか確認する。承知の上で続けるなら `--force-mismatch`。セグメント id が整数でないグラフ（minigraph の `s1` など）では、GAF も元の名前のまま渡す（[セグメント名](usage-prep.md#アノテーションとリードも一緒に)） |
| 出力が root 所有になる | `-u $(id -u):$(id -g)` を付けて実行する |
| 「重なりのある L 行が … 本ある」で止まる | 重なりのある（blunt でない）GFA。de Bruijn グラフ（Bifrost・Cuttlefish など）は重なりを除いた GFA に変換してから渡す |
| 「--gff-dir … に、どのパスの GFF も無い」で止まる | ファイル名がパス名の sample と合っていない。表示された期待名（`<sample>.gff3.gz` など）に合わせる |
| 遺伝子が 0 件・一部の株だけ遺伝子が無い | GFF の seqid（第 1 列）がパス名のコンティグと違う（例: GFF は `NC_001133.9`、パスは `S288C#0#chrI`）。genes のログに「グラフの seqid の行が 1 行も無い」と出る |
| 参照座標（Ref bp）・座標での移動が無い | 参照のパスが選べていない。ログの「参照: …（理由）」を見て、違えば `--ref-key` で sample を指定する |
| `--band`/`--gene` を渡したのに注釈が付かない | パスの無いグラフ（rGFA・de Bruijn）では写せないので飛ばす。パスのあるグラフなら seqid と参照のコンティグ名の一致を確認する |

## コンテナのビルド

| 症状 | 原因と対処 |
|---|---|
| 依存の取得で止まる | ビルドには外向き通信が要る。プロキシ環境では設定を渡す |
| Apptainer の build がマウントで失敗 | サイト設定の bind。`env -u APPTAINER_BINDPATH apptainer build ...` |
| 権限の拒否で起動できない | 元ファイルの権限がイメージに入り込んでいる。同梱の定義は対策済み |
| ライブラリが見つからない | 実行段のイメージに共有ライブラリが不足。同梱の定義は `ldd` で検査してから焼く |
| 変な `import` エラー | ホストの `~/.local` を拾っている。`--cleanenv` と `PYTHONNOUSERSITE=1`（同梱イメージは設定済み） |
